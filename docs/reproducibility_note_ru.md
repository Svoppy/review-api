# Примечание по воспроизводимости

Дата: `2026-05-28`

## 1. Что воспроизводится уже сейчас

- структура пакета и импорт модуля `reviewguard`;
- конвейер нормализации данных;
- вычисление метрик;
- часть unit-тестов, не зависящих от системных временных каталогов;
- документированный training workflow и формат экспортируемых артефактов.

## 2. Что проверено в текущей среде

Команда:

```bash
pytest tests/test_training_metrics.py tests/test_inference_artifacts.py tests/test_datasets.py -q
```

Результат:

- `12 passed`
- `3 skipped`

Это подтверждает корректность части ядра проекта, связанной с метриками, базовой логикой датасетов и конфигурацией импорта.

## 3. Текущий внешний блокер

Полный `pytest` в данной среде упирается не в логику проекта, а в `PermissionError` при работе со временными каталогами Windows (`playwright-pytest-*` и related temp cleanup behavior). Это environment-specific ограничение текущего окружения запуска.

Дополнительные внешние ограничения текущего snapshot:

- в `data/` отсутствуют реальные подготовленные корпуса;
- в репозитории не присутствуют обученные `models/` артефакты;
- в активном Python-окружении отсутствуют `torch` и `transformers`, поэтому полноценный training/inference smoke run в этой среде невозможен.

Следовательно, на текущем этапе корректно формулировать вывод так:

- проект частично воспроизводим и проверен;
- полный тестовый прогон требует либо другой среды, либо явной изоляции системного temp-path.

## 4. Что нужно сделать для полной воспроизводимости

1. Выделить стабильный доступный temp-path для `pytest`.
2. Убедиться, что cleanup временных директорий не блокируется политиками среды.
3. Повторить полный `pytest`.
4. Зафиксировать итоговую команду прогона и ожидаемый результат в основном README или workflow guide.

## 5. Как это описывать в статье

В диссертационном тексте нельзя писать, что “все тесты воспроизводимо проходят” до завершения полной проверки. Корректная формулировка на текущем этапе:

> Репозиторий содержит воспроизводимый исследовательский контур и набор автоматизированных тестов для ключевых компонентов. В текущей среде часть тестов подтверждена фактическим прогоном, тогда как полный прогон требует дополнительной настройки системного временного окружения.
